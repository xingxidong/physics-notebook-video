# 从文章上成一节课

源文章的各节、编号公式、图号与分图、作者提出的读图或计算活动都进入清单。拿原文和实际讲稿作对照，分别指出缺失、只给结果、已展开的部分。论文的背景和参考文献可放入讲义的来源说明。实质内容对应到口播 cue、可见板书和学生做的推理。

在 lesson.json 设置 `"source_type":"article"`、`"article_coverage":"article-map.json"`。对照表的 `source` 写原件名称和版本，`items` 为条目列表。教学条目写 `source_ref`、`student_task`、`cues` 和 `actions`，动作 ID 应在列出的实际句段中。资料背景可写 `kind:"background"`、`source_ref` 和 `note`。项目的教案审阅与质量检查会定位缺少讲解或笔迹的条目；表中的证据是否充分由制课者对照原文、逐字稿和实际画面判断。

先用同一作者、同一音色已完成的课，计算实际发声期间的正常语速。预计时长用实际要讲的字数除以该语速；同时出现的板书和动画只计一次。将所用语速、实录依据、各段新增的学生任务和时长列入教案。宁可多讲一个真正用到的例子，也应保留学生能顺着写下来的中间式。

`duration_plan.minimum_minutes`（时长计划内的字段）表示本次硬下限；作者个人库的文章课偏好作为缺省值。本次明确给了新的时长或下限时按本次要求。加长版把同一音色已完成课程的正式时间轴存入项目，并在时长计划的 `reference_timeline` 填入相对路径。教案用旧版实录语速和新版实际口播重算预计发声时间，导出后另行对照相同句子的实录和笔迹。开场、翻页、字幕、静止画面、全局语速和笔迹速度均不得拿来补时长。先核教案，再以 `course.py quality-check PROJECT --stage final --video-file FILE --strict` 检查交付 MP4。低于下限时，补教学内容并重新走审阅。
