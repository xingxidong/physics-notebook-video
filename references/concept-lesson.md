# 新授课

使用 `kind:"concept"`。从教材、章节目标或用户点名的物理概念出发，先确定学生学完后应能复述什么、能解释哪种现象、能在哪些条件下使用结论。将教材中的关键定义、定律、量的方向和适用条件提取到知识点列表。写口播与设计动画前，先完成[整课编排与课末检查](course-planning.md)。

## 先分知识点，再排板书

先列出本节要教的知识点。每段讲清一项新知识，为它写一句具体的学习目标，例如「能用末位置减初位置，判断一维位移的方向」。先判断最适合这项内容的推进路线，再安排观察、对照、建模、推导、正式结论和应用中的必要环节。它们不套统一顺序。正式结论在学生已经有足够依据时写下，应用放在结论之后。对照整课提纲通读一遍，确认每段从一个具体情景、现象或问题起步，在学生能复述的结论处收住。

| 阶段 | 老师怎样讲 | 画面上写什么 |
|---|---|---|
| 引入 | 给出一个具体情景或现象，让学生先看清研究谁、在比什么。需要学生判断时提出明确的问题。 | 给出提问时，写出完整问题和已知条件。画出研究对象，标明马上会用到的已知量。 |
| 讲解 | 沿着同一个问题看现象、作对照或推导。每次改变条件时说明保留了什么。读图说清哪个点、哪条线或哪个方向进入公式。 | 逐步补辅助图、数值、物理箭头和必要中间式。图、条件和推导尽量同页，跨页时把接下来要用的关系留在下一页。 |
| 强调 | 用一句话解释刚得到的结论，明确学生要记下的关键词、物理意义与适用条件。 | 写全概念或定律的名称、定义或结论，保留同页相关公式、符号含义与条件。用颜色或下划线突出最关键的一句或一个量。 |
| 应用检查 | 换一个条件或给出一道短题，让学生使用刚才的定义或定律并说明理由。可以用一句判断题检查理解。 | 写下问题，再写核心答案或依据。需要计算时，沿题图展示解题过程。 |

这些教学动作可以在同一张板书上完成，也可以根据内容重排。例如从反例出发的定义课先对照再命名，定律课可以先观察和建模，证明课可以先提出要证的关系。每一段始终保留四类证据：学生面对的问题、看得到的依据、可抄录的结论、结论在新情境中的使用。板书直接写具体内容，例如「这次位移向哪边？」或「位移等于末位置减初位置」。课程源里的教学拍用于备课和审查。

### 提问与情景图标注

- 老师问学生判断、预测或计算时，在对应口播段把完整问题逐笔写在画面上。条件已在旁边的图中标清时，用相同的点名或符号指回图。答案放到后面的口播段。学生可以自行暂停思考或抄写。
- 动画开始或推导用到某个量时，学生应能在图上找到它。把对象、参考点、原点和正方向标在相应位置。参与推导的长度、角度、时间、速度、力等标出符号，已知具体值时带单位。矢量箭头写清是谁的量、相对于谁或由谁施加。比较不同帧或视角时，标出时刻、状态和参考系。
- 看一遍开场、关键转折和结束帧。对照口播逐一检查标注所在位置、首次出现时机和沿运动过程的可读性。删去这段用不到的标注。检查文字、公式、标签和图互不遮挡。

### 课程源如何登记

新授课用 `concept_units`。每个单元记录下面这些字段。单元按顺序覆盖全部口播。旧格式仍可用四个阶段字段；新课优先使用 `stages`，列出实际采用的教学拍和它们的首条 cue。长课的章节 `fragment.json` 一起交付 `concept_units`、`knowledge_points` 和 `pages`。

| 字段 | 内容 |
|---|---|
| `id`、`focus` | 单元编号和本段真正要讲清的一项新知识。 |
| `stages` | 推荐。每项含 `purpose` 和 `cue`。可用 `orient`、`observe`、`contrast`、`model`、`reason`、`derive`、`anchor`、`apply`、`recap`，按本知识的真实逻辑排列。`anchor` 是正式结论落笔，`apply` 是结论后的使用。 |
| `introduce_cue`、`explain_cue`、`emphasize_cue`、`apply_cue` | 兼容旧课的四阶段格式。新课不必为了迁就格式而打乱教学逻辑。 |
| `knowledge_point_ids` | 本段在强调阶段写完的正式结论 ID，来自 `knowledge_points`。 |
| `questions` | 每条含 `cue`、`answer_cue`、`text`、`action_ids`。正文与提问时真实写出的文字一致。应用检查阶段至少有一条问题及其回答。 |
| `scene_labels` | 每条含 `page_id`、`action_id`、`first_use_cue`，指向本页真实写出的量名、符号或数值。纯代数段可用 `scene_not_applicable` 写明原因。 |

`course.py teaching-check` 在 `concept_sequence` 中报告教学拍顺序、问题和标注的板书链接。它检查正式结论在应用之前出现，问题已上板且有后续回答，图中量在使用前可见。还要对照预览，核对问题和标注何时出现在画面上，读一遍口播，确认学生能顺着图听懂本段重点。

## 让口播跟着图和板书走

先确定本段实际显示的图、公式和条件，口播用它们的量名和方向说话。在 `lesson.json` 中用稳定的动作 ID 关联正式结论和推导，在 `speech-plan.json` 中用同一 cue 的 ID 保存自然口语。用动作的 `at` 将落笔对齐到口播关键词。对需播放、暂停或比较的真实物理状态，用 `scene_events` 和现有的物理场景。静态的几何、定义或代数关系可用分步配图，说明本页为何采用静态对照。见[语义场景](semantic-scenes.md)。

思考题先写在板书上，待条件和图形明确后再讲答案。观众需要时可以暂停。把完整定义、定律和公式安排在讲解中写完，学生可自行暂停抄录。用 `knowledge-board-report.json` 确认这些笔迹在换页前全部写出。见[知识点结论板书](knowledge-board.md)。

## 从完整示例开始

```sh
python3 SKILL/scripts/course.py init PROJECT --kind concept
python3 SKILL/scripts/course.py teaching-check PROJECT
python3 SKILL/scripts/course.py build PROJECT --draft
```

示例从一条候选位移式进入，对照速度乘时间和加速度乘时间的量纲，再逐笔写出同量纲的量相加这一原则，最后用一道短题让学生选出具有长度量纲的量。改成用户的章节时，同步替换示例中的文字、图、知识点和口播。
