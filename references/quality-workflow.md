# 重难点与制作复查

## 备课时决定怎样讲通

用学生已有知识写清这节课的起点。新授课延续整课编排的引入、讲解、强调、应用检查；各段解决一个可说清的问题。在讲解前想好学生究竟会卡在建立模型、读图、选规律还是某一步运算。相应地增加对照图、同图两种状态、逐项对应的式子或必要的中间步。讲通以后把完整结论写在板书上，再用改变一个条件的问题让学生使用结论。

重点落实到三处：讲稿中的一句解释、同一时段能看到的图或关系式、随后能独立完成的一次判断。比如非线性网络的重点是两个节点方程共享同一个桥电流，图上保留那条支路，板书并列两个表示式，口播说清从哪个节点看是流入、从哪个节点看是流出。写“重点讲解消元”仍需补到这个程度。

习题课在课程源中设置：

```json
{
  "review_notes": {
    "focus": "两条节点方程含有同一股桥电流",
    "difficulty": "先沿图说清流入与流出，再将同一股电流在两个式子中单列",
    "outcome": "能独立从电路图列出两个节点方程",
    "focus_actions": [
      {"page":"p02", "cue":"bridge-current", "action_id":"bridge-equality"}
    ]
  }
}
```

关联的文字或公式使用 `emphasis:true` 或明确的强调色。在完整主线中挑出决定下一步的关系，给它与普通代入不同的时间和视觉强调。新授课沿用 `key_point`、`difficulty`、`knowledge_points` 与 `emphasis`，参见[课程编排](course-planning.md)。

## 自然课堂表达

写完初稿，连着读相邻两段：上一段留下什么，眼前这句话在指什么，下一步为什么这样做。把依据补进讲稿，再删去重复的流程预告。开场从本课的问题或图中现象进入，结尾回收本节建立的具体关系。正式定义和结论在板书完整写出，口播解释量的含义、取法和成立条件。

例如“接下来我们将利用节点法分析这一复杂网络”可改为“看 C 点。A 送来的电流，在这里分成两股。”接着沿图写三条支路，讲到公式时说明每一项从哪条线来。“由此可见结果成立”改成具体的“同一个函数值只对应一个自变量，所以两个括号里的量相等”。采用与本页图和推导相符的说法。

讲稿复读与实际配音分别检查。文字顺口之后，声音仍可能出现术语错读、拖字、吞字、重音错位或句中卡壳。按[课堂表达与节奏](classroom-delivery.md)回听上下文，依据听到的问题改句子、读音或句群切分。声音问题修改后再听同一处衔接。

复查开头时停在第一句口播之前，确认主模型、对象名和必要标注已完整可见。复查结尾时连看最后一个推导段和总结段。总结先回到图中的模型或开场问题，再指出决定结论的关系，最后说清所得结果或可用场景。学生在听总结时能看到它所指的图和式子，最后一个字说完再结束画面。不要用“这节课到这里”代替总结。

## 两次运行检查

```sh
python3 SKILL/scripts/course.py quality-check PROJECT --stage plan
python3 SKILL/scripts/course.py quality-check PROJECT --stage final
```

第一次在出教案之前使用，不合成声音。检查当前题目/概念工作流、讲稿、板书、时长编排、讲义和原生预览是否齐全，输出 `制作检查.md` 和 `quality-report.json`。旧项目缺少新增字段会收到补充提示，源文件保持原样。

`review-plan` 会自动执行这次检查，把清单链接和具体问题写入教案。教学材料缺失或关联错误需要修复后再登记教案确认；词句和节奏的提示结合上下文处理。

第二次读取当前配音时间轴，复查分段时长、实际音频静音、术语试听位置及成片长度与音轨。课程源或相关素材改变时，先重建对应内容。可加 `--strict`，在自动检查发现待处理问题时返回失败状态，方便批量制作脚本使用。

报告中的 `findings` 给出所在区域、页面或句段、问题和处理方向。确定属于需要保留的自然停顿或有效表达时，在制作记录中写明原因。机械静音裁剪可能破坏连读，先回听再决定。连续两次局部修复仍没有改善时，把该段试听和具体问题交给用户选择处理方式，已有缓存继续保留。

`coverage` 只说明实际检查范围：教学字段和依赖、词句线索、已声明的时间检查点、模型抽样轨迹或对象框、音频信号、成片时长与音轨。`manual_review` 保留尚需看的问题。抽样几何检查无法覆盖任意形状的全部接触，音频电平检查也无法判定所有拖字和真实语气。实际观看时查看开始、接触前后、极值、转折、结论；声音按 `voice-report.json` 的 `listening_checks` 连听前后句。

修复顺序通常是物理关系与必要推导、图文标注与显示先后、讲稿与读音、局部节奏和视觉细节。改动后只重做受影响的缓存段，并在更新后的成片里复看一次。反馈区分已运行的自动检查、实际观看试听和待处理项。
